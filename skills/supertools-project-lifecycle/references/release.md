# 发布与交付复验

## 确认目标与入口

先确定用户要准备、执行还是核实哪次交付。目标可以是运行中的服务、包仓库、应用商店或交给接收方的一份文件。同一次改版有多个独立交付对象时，分别确认目标、候选版本、验收条件和恢复方式。

从可取得的项目说明、构建配置、交接单或发布回执找出生效的入口。若证据冲突，对照维护手册、最近成功回执及候选版本的配置，核实哪条路径已经接管。首次发行可依据用户选定的渠道与现有说明。若目的地或生效入口仍有歧义，先完成能够执行的就绪检查，列明需要确认的那一项。

## 按用户请求执行

- **准备发布**时，按该项目的办法构建或取得候选，核对必需用例是否覆盖同一产物、版本和运行模式，报告已就绪或具体缺项。只有旧版通过、当前用例失败或未完成时，指出需补验的部分。
- **执行发布**时，核对授权覆盖的接收方、版本和影响，使用现有流水线、平台操作或人工交付流程。作业在运行或交付回执不明时，先查询该次尝试。如果一步作业同时构建、测试和发布，触发前核实其实际作用与发布条件。仅项目选用 CloudBase 静态托管并直接上传时，参见[静态目录上传示例](cloudbase.md)。
- **核实交付**时，把实际收到或运行的版本与已验收候选对应起来。沿用接收方能核对的标识，例如不可变修订、发行方提供的摘要或签收单上的批次。分支名、可复用标签或文件名无法区分两次构建时，查其对应的具体产物。交付回执和业务用例分别记录。

## 从接收方的位置复验

| 交付对象 | 可复用的版本证据 | 一条可观察的业务复验 |
| --- | --- | --- |
| 网站或服务 | 实际入口对应的资源、镜像摘要或部署修订 | 在该入口用允许的测试数据重跑原用例 |
| CLI、库或插件 | 从目标渠道取得的归档、已安装版本或可信摘要 | 在干净的消费环境中导入或调用该版本，核对原用例的输出 |
| 安装包、商店或离线交付 | 分发渠道的版本、收件回执或目标设备上的安装记录 | 验证目标设备上的操作，需接收方操作时保留待签收项 |

根据实际对象选一条合适路径。例如，内网制品库收到新包后，可用仅从该库安装的副本运行样例，记录已安装版本与输出。若只能看到发送方记录，就报告已发出的版本以及待接收方验证的用例。只有该目标必需的业务检查均通过后，才更新最近一次验证通过的版本。涉及配置、持久化数据或协议变化时，按项目恢复手册核对旧版本兼容性。
