# 按需巡检与恢复

## 确认使用者遇到的问题

1. 核对交付对象、使用环境、时间范围和实际使用的版本。比较最近一次验证通过的版本，以及故障前后的发布、安装或配置变化。
2. 从出现问题的位置核实一条受影响的用户操作。服务可检查入口、就绪状态与现有监控，库或 CLI 可核对已安装版本、调用输入与错误输出，离线设备可核对操作人员的现场回执。使用团队已有证据定位最早出现异常的环节，报告现象与影响范围。
3. 如果某项数据无法读取，写清已经检查了什么、仍缺哪项证据。重启、回滚和其他变更按本次授权执行。正在部署、数据库迁移或数据格式变化可能影响回滚时，先对照项目恢复手册核实兼容性。

## 恢复一个版本

1. 用户指定版本时核实该版本及其已知验收状态。只说“上一版”时，从同一对象、环境与渠道查找最近一次业务验收通过的版本，并说明依据。有多个可能的接收方或恢复目标时，先消除歧义。核对当前版本、旧产物、数据兼容性与影响范围。
2. 在已有授权内使用项目的恢复入口。服务可回切，客户端可按手册恢复指定安装包，库可由受影响的消费工程恢复原依赖版本。核实目标及留存产物的可信标识，找不到匹配产物时记录阻塞。修复一台客户端与变更共享分发渠道的影响范围不同。
3. 从实际使用入口确认恢复版本，重跑导致事故的业务用例。若需接收方确认，记录已完成的步骤与待复验项。将恢复作为一次新尝试关联旧记录，操作超时先核对目标状态再决定是否重试。
